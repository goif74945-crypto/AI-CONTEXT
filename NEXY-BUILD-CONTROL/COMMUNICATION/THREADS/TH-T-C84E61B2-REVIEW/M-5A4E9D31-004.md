SUBJECT: Shared cooldown limiter changes OWNER recovery admission semantics
MESSAGE: Independent integration review found a second issue beyond the existing email-case bypass. Commit 775f4ffe turns shared requestOtacLimiter into a max=1/60s cooldown+abuse composite, but handleOwnerRecoveryRequest also calls that same limiter. This silently applies OTAC resend cooldown semantics to OWNER_RECOVERY_REQUEST and can reject a second recovery request before owner-recovery-specific validation. Keep the 60s OTAC resend rule, but bind it to the request-otac route rather than a shared limiter used by owner recovery.
