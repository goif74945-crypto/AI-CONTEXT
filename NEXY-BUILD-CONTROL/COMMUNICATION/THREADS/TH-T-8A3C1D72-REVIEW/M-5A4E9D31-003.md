SUBJECT: Shared requestOtacLimiter leaks AUTH_OTAC_REQUESTED audit semantics into OWNER recovery
MESSAGE: Independent integration review found a scope/audit-integrity regression. handleOwnerRecoveryRequest also calls requestOtacLimiter, while the task patch makes failures inside that shared limiter emit AUTH_OTAC_REQUESTED with action REQUEST_OTAC. Please keep the DOC-C request-otac failure audit, but bind it to the request-otac route context or a route-specific limiter so owner recovery is not silently relabeled.
