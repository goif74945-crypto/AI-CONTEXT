# WORKFLOW — ARTIFACT CREATION

## Goal
Create a finished usable artifact rather than an outline pretending to be one.

## Supported artifact classes
Examples:
- document/report/spec;
- code/project;
- dataset/schema;
- presentation;
- image/media brief;
- configuration;
- prompt/system instruction;
- plan/runbook;
- model/context package.

## Pipeline
`PURPOSE → AUDIENCE/CONSUMER → FORMAT → SOURCE → STRUCTURE → BUILD → VALIDATE → PACKAGE`

## Procedure
1. Define who/what will consume the artifact.
2. Lock format and acceptance criteria.
3. Resolve authoritative input/source material.
4. Build the internal structure before polish.
5. Produce the complete artifact.
6. Validate syntax/format/content invariants.
7. Test usability in its target environment when possible.
8. Package with version/provenance where useful.
9. Record limitations and exact status.

## Creation quality
A complete artifact should be:
- internally consistent;
- directly usable;
- source-grounded where factual;
- free of placeholders unless explicitly requested;
- easy for the next human/AI/tool to consume.

## AI-facing artifacts
Prefer:
- explicit schemas;
- stable headings/IDs;
- machine-readable status;
- examples;
- failure semantics;
- minimal ambiguity.
