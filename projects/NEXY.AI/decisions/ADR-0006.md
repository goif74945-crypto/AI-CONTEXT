# ADR-0006 — DOC-C governs build; DOC-E governs deployment proof

**Record type:** SOURCE_DERIVED_ADR  
**Authority:** Document hierarchy  
**Scope:** CURRENT_REQUIRED

## CONTEXT
The source contains vision, law, build, product and deployment-evidence material that must not be treated as equal build authority.

## OPTIONS
1. Treat all documents equally
2. Use newest prose regardless of class
3. Separate document authorities by purpose

## DECISION
DOC-C defines current build obligations; DOC-E defines deployment approval evidence; DOC-B governs system law; DOC-A/D remain vision/product context within their authority.

## WHY
- Prevents future vision from silently becoming current requirement.
- Prevents code completion from becoming deployment proof.
- Makes conflicts resolvable.

## CONSEQUENCES
- Future systems can exist in ontology without current build obligation.
- Deployment requires evidence beyond code/tests.
- Audits must tag authority class.

## SUPERSEDES
None explicitly recorded.

## ROLLBACK / CHANGE BOUNDARY
Requires explicit source hierarchy revision.
