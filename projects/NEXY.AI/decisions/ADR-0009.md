# ADR-0009 — No automatic retry by default for authoritative work

**Record type:** SOURCE_DERIVED_ADR  
**Authority:** DOC-C  
**Scope:** CURRENT_REQUIRED

## CONTEXT
Retries can duplicate side effects or create hidden state unless idempotency/safety is proven.

## OPTIONS
1. Retry every failure
2. Never retry anything
3. Default no auto-retry; permit only explicitly safe/idempotent retry paths

## DECISION
Automatic retry is not the default; safe retry requires explicit contract/idempotency semantics.

## WHY
- Protects authoritative state from duplicate execution.
- Makes failures visible.
- Matches queue/recovery discipline.

## CONSEQUENCES
- Workers/jobs need idempotency keys.
- Recovery may start a new execution cycle rather than resume old work.

## SUPERSEDES
None explicitly recorded.

## ROLLBACK / CHANGE BOUNDARY
Config/contract change only through audited versioned path.
