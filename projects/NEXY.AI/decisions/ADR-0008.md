# ADR-0008 — Keep NEXY state machines semantically separate

**Record type:** SOURCE_DERIVED_ADR  
**Authority:** Final Architecture, DOC-C and subsystem specs  
**Scope:** CROSS_SYSTEM

## CONTEXT
NEXY has constitutional, execution, app, publication, capability, queue, risk and transfer state machines with overlapping labels.

## OPTIONS
1. Merge all states into one global enum
2. Treat states as informal labels
3. Maintain separate FSM identities and explicit cross-events/contracts

## DECISION
Each FSM remains independently scoped; identical state names across FSMs do not imply identical semantics.

## WHY
- Avoids invalid transition mixing.
- Preserves subsystem ownership.
- Enables machine validation.

## CONSEQUENCES
- Cross-system behavior requires explicit events/contracts.
- AI must resolve FSM identity before changing transitions.

## SUPERSEDES
None explicitly recorded.

## ROLLBACK / CHANGE BOUNDARY
Requires explicit architecture redesign and migration of every affected transition contract.
