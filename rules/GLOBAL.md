# GLOBAL RULES

## G0 — Purpose
AI-CONTEXT exists to let any capable AI continue work with minimal reconstruction and maximal factual fidelity.

## G1 — No silent guessing
Material unknowns remain UNKNOWN. Safe reversible inference must be labeled. Irreversible/high-impact work blocks on unresolved material ambiguity.

## G2 — Scope is a hard boundary
Touch only the target and dependencies required to satisfy the task. Adjacent improvement is not authorization.

## G3 — Authority before interpretation
Resolve which source/spec/state controls the question before using conflicting information.

## G4 — Current state before mutation
For repository/runtime work, inspect the real current target before modifying it. Expected state is a precondition, not a substitute for observation.

## G5 — Evidence before status
Never mark PASS/COMPLETE from intention, prose, filenames, code presence, or expected behavior alone.

## G6 — Design != implementation != runtime != deployment
Keep these classes separate in every status report and context record.

## G7 — Preserve provenance
Durable facts should identify their source class and, when useful, exact file/commit/evidence.

## G8 — Preserve contradictions
Do not erase historical or authority conflicts by silently choosing a preferred narrative.

## G9 — No hidden repair
No silent fallback, force, auto-fix, or scope change when it changes semantics.

## G10 — Context-window survival
For large work use streaming capture and checkpoints. Do not depend on a single model session retaining everything.

## G11 — Model independence
Persist explicit rules and state, not model-private reasoning.

## G12 — Protect secrets
Never commit passwords, API keys, session tokens, private credentials, or equivalent secrets to AI-CONTEXT.

## G13 — Resume quality
Every durable task record should make it possible for another AI to determine:
- what was requested;
- what was inspected;
- what changed;
- what passed/failed;
- what remains;
- what must not be touched.

## G14 — Status vocabulary
Use PASS / FAIL / PARTIAL / BLOCKED / NOT_VERIFIED / UNKNOWN / CONFLICT. Define project-specific states separately.

## G15 — Integrity priority
When speed/completeness conflicts with correctness or evidence integrity, correctness/evidence wins.
