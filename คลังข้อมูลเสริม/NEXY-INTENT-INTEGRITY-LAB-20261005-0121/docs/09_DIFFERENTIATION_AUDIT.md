## Differentiated primary contribution of this project

This project was extended with an executable **Least-Authority Delegation Capsule** subsystem. Its primary question is not “did this proposal violate the parent contract?” but:

> Can a parent contract deterministically attenuate its authority into a sealed child-agent handoff where capabilities can only stay equal or become narrower?

The subsystem enforces:

- parent contract must be fully `ADMIT`, not `REVIEW` or `FREEZE`;
- child inputs must be a subset of parent inputs;
- child required outputs must be a subset of parent required outputs;
- child scope must be lexically covered by parent `inScope`;
- child scope must remain disjoint from parent `outOfScope` and `protectedScope`;
- parent constraints, immutable rules, required behavior, forbidden rules, edge cases, failure conditions, validation, acceptance, protected scope, and stop conditions cannot be removed;
- child may add tighter constraints/forbidden/stop conditions;
- exact ordered authority chain must be preserved;
- capsule is sealed and independently re-verifiable against the parent contract seal.
