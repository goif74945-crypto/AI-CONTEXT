# Capability Half-Life Model
> AI-PROPOSED CONCEPT
A capability can still run while becoming economically, semantically, or operationally obsolete.
Record owner, authoritative spec, provider/model/data dependencies, latency/cost envelopes, quality floor, security assumptions, fallback, migration adapter, last verification, and expiry trigger.
Capability half-life = estimated interval until a critical assumption requires re-verification, not until code stops.
Triggers include API retirement, model replacement, price/policy/schema changes, benchmark regression, SLO failure, security-boundary change, or superseded requirements.
Initial values are hypotheses until calibrated from measured history.
