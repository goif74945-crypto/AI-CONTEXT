# AI-Proposed Future Extensions

Every item here is `AI_PROPOSED / NOT_CURRENT_NEXY_REQUIREMENT / NOT_IMPLEMENTED`.

## GCG futures
- weighted acceptance criteria with authority-owned weights;
- requirement-to-test/evidence contribution edges;
- change-impact delta showing which work becomes orphaned after objective edits;
- a “value debt” report for long-lived work with no current acceptance path.

## VCC futures
- typed schema compatibility beyond string type names;
- capability substitution witnesses when a tool becomes unavailable;
- privacy/residency constraints bound to exact data fields;
- benchmarked plan selection using measured latency/reliability, but only when evidence is current and identity-bound.

## ACFG futures
- consumer-specific schema validators;
- archive/portable-package checks;
- rendering or openability probes in isolated sandboxes;
- accessibility/readability profiles where the consumer contract explicitly requires them.

## SCTG futures
- SBOM ingestion;
- signed provenance attestations;
- vulnerability advisory correlation from authoritative feeds;
- update-diff admission requiring fresh trust evidence before changing a pinned dependency.

## MPC futures
- role-specific mastery graphs;
- verified completion receipts for prerequisite steps;
- optional “teach by safe sandbox” exercises;
- path recompile when capabilities or product surfaces change;
- multilingual instructional content while keeping graph semantics language-neutral.

## Cross-engine future

A future “Leverage Receipt” could bind all five outputs to one task snapshot and show:
- why the work contributes to the objective;
- which capabilities can perform it;
- whether dependencies are admissible;
- whether the final artifact fits its destination;
- whether the human operator has the declared prerequisite path.

This receipt must remain explanatory/advisory and must never become an authority shortcut around existing NEXY controls.
