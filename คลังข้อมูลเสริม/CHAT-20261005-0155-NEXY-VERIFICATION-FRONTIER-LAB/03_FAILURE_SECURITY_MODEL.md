# Cross-System Failure & Security Model

**Status:** AI-PROPOSED / ADVISORY / NON-CANONICAL

## Trust boundaries

The five prototypes consume data that may be untrusted, stale, incomplete, or generated by another AI. None of that input gains authority merely by reaching this lab. Integration adapters must bind identity, provenance, version, and required evidence class before results influence a NEXY verification workflow.

## Cross-system invariants

- No engine grants release/authorization authority.
- No engine changes an upstream FREEZE into PASS.
- No engine treats model confidence as evidence.
- Evidence classes are explicit strings and are never silently promoted.
- Invalid configuration is rejected instead of repaired by guessing.
- Deterministic ordering/tie-breaking is used wherever the engine selects or enumerates outputs.
- Core algorithms require no network access, credentials, or external model calls.

## Threat / failure table

| Threat or failure | Primary control | Residual limitation |
|---|---|---|
| Ambiguous hostile JSON | BPPL duplicate/Unicode/nonfinite/limit rejection | production ingress still needs byte limits / streaming defenses |
| Huge failing payload obscures cause | FWD signature-preserving reduction | greedy local minimum, expensive oracle can dominate runtime |
| Cheap static check wrongly substitutes behavior proof | VPO explicit evidence-class membership | upstream claim policy must itself be correct |
| Tests are green but insensitive | CMAE deterministic semantic mutants | mutation operator set is not exhaustive |
| Prohibition linked only to happy-path test | NSCA polarity + evidence-class qualification | relies on trustworthy evidence metadata |
| Stateful/nondeterministic failure oracle | FWD final signature re-check | cannot make an unstable oracle trustworthy |
| Exponential exact portfolio planning | VPO explicit claim-count limit | large instances need another algorithm with declared optimality limits |
| Vacuous mutation score from zero mutation budget | CMAE rejects non-positive `max_mutants` | score still applies only to generated operators |

## Data handling

Reference implementations operate on in-memory structures and do not persist secrets. Evidence logs generated by this lab contain test names and statuses only. Future adapters must redact or minimize sensitive request content before storing reduced witnesses or mutation fixtures.

## Promotion requirements

Production use requires project-specific schema adapters, exact-revision integration tests, performance limits, abuse tests, provenance binding, and explicit NEXY mutation authorization. Until those are present, these outputs remain supplementary engineering proposals.
