# Integration Contract

## Proposed future placement
ICF may sit beside a future Lo4 idea/research intake pipeline, below User Law and below every canonical NEXY release/authority boundary.

Conceptual placement:

`Lo4 idea intake -> explicit utility/overlap/change-surface evidence -> ICF -> bounded pilot proposal -> external human/formal promotion process`

## Adapters required for real NEXY use
1. Proposal metadata adapter that supplies explicit objective intervals and conservative values.
2. Collision-evidence producer that supplies pairwise overlap with provenance/basis IDs.
3. Architecture-impact adapter that declares change surfaces rather than hiding them in prose.
4. Capability/dependency graph adapter.
5. Pilot execution/consent system that remains outside ICF.

## Non-bypass law
ICF output must never:
- authorize protected state mutation;
- weaken NEXY verification evidence requirements;
- override a canonical requirement;
- auto-promote Lo4 content;
- reinterpret `READY_FOR_BOUNDED_PILOT_REVIEW` as deployment approval.

Standalone local E1/E2/E3-lab evidence only. Actual NEXY runtime integration is `NOT_VERIFIED` by design because the protected NEXY.AI repository was not modified or instrumented.
