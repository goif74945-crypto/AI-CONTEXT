# AI.AI v0.4.0 | Engineering release verification

Date: 2026-10-09. Product: independent AI.AI local Git `main` repository; no remote AI.AI GitHub repository was created.

## Core changes (evidence-first)

- Raised strict tool count from 30 to 39, preserving all existing 30 actions. Added nine observation/verification controls: desktop wait-window and inspect OCR text, browser wait-role, wait-URL, assert-value, inspect controls, Android wait-text, inspect controls, and file.assert_sha256.
- `ai_ai/assurance.py` is a deterministic preflight reviewer; browser plans must name their own `browser.open` before executing later browser actions; coordinate or unverified actions raise user-visible warnings. The policy is not an automated task-success proof.
- Browser requests are intercepted before dispatch via Playwright context routing and limited to the exact approved `(scheme, host, port)`; service workers are blocked. Redirects, externally linked targets and wrong-origin follow-on operations are additionally checked. Same-origin malicious JavaScript, unhandled WebSockets and browser vulnerabilities are NOT covered.
- Desktop OCR text-click and Android UI text-tap require two fresh observations within an 8-pixel drift tolerance. If a target moves or goes ambiguous, no tap/click occurs. Stop is checked again before injecting the action.
- Emergency stop invalidates plans still in LLM/OCR planning, and cancels before external model invocation if it was signaled during OCR. Script cancellation on POSIX attempts to kill its new process group. These controls remain best effort because operating systems and apps can cause irreversible effects.
- Browser/Android control inspection strips input *values* and password fields and truncates output; local UI contents are still potentially sensitive. No automatic remote data upload is added.

## Evidence and remaining gates

- Python automated test suite includes existing v0.3 cases plus new v0.4 regression tests for stale UI, race cancellations, DOM assertions, active-window and Android waits, website allowlisting, file SHA verification, plan scope, and read-only inspection.
- Run `python -m pytest -o addopts='' -q` and record count as execution evidence rather than inferring success from this design document.
- Node clap authorization tests: `node --test tests-js/*.test.mjs`.
- Real Chromium injected HTML DOM: inspection, wait-role, fill, assert-value, click-role, assert-text, screenshot and disabled-button rejection: tested locally. These are **real DOM interactions**, not a proof of successful web navigation.
- **Blocked**: Chromium actual navigation via HTTP(S) returned `net::ERR_BLOCKED_BY_ADMINISTRATOR`, including a fixture URL despite Playwright intercept; therefore network end-to-end browser navigation is NOT VERIFIED.
- **Not verified**: physical desktop on user machine, Android on user's device, microphone false-trigger rates, app-to-app end-to-end success, native Android/iOS accessibility apps, untrusted-code sandbox, or universal task accuracy.
- **Remote GitHub product**: `goif74945-crypto/AI.AI` was not previously available; this distribution is a LOCAL Git project with only `main`. CI is defined but has not been executed remotely.

## Exit state

Locally exercised core components and test assertions are not a production-grade autonomous computer-use product. Residual risks must remain visible; do not fabricate percentages or imply no bugs remain.
