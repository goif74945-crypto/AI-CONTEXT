## Changes from v0.2

1. Exact focus guards: optional `window_title` for desktop click, type, hotkey, scroll and OCR click; explicit `desktop.assert_window`; guard before OCR click **and again immediately after OCR**.
2. Browser navigation approval: pin origin after explicit open; block wrong-site redirects, off-origin clickable links, inspectable form actions, new tabs and wrong-origin follow-up actions; `browser.assert_url` enables postcondition tests.
3. Semantic `browser.click_role` uses accessibility role/name; requires unique visible and enabled target. Guards external targets before click.
4. Android UI text click now prefers clickable ancestor, refuses disabled ancestors; passively asserting text remains possible.
5. LLM output is checked against operator's original request for text labels, URLs, paths, package names, and coordinates. OCR evidence cannot itself authorize unrequested actions.
6. Frontend microphone permission race fixed: Stop/Discard invalidates stale pending `getUserMedia` permissions, closing late-returning tracks.
7. New `@window=Title` deterministic desktop input grammar; no nested guards.
8. Optional system Chromium `AI_AI_BROWSER_EXECUTABLE`, explicit absolute existing path.
9. 30 strictly typed actions, maximum 24 steps, reviewed before execution; wheel resources and UI version updated.

## Known limitations / must not claim complete

- Focus title checks are not OS application authentication; platforms without active-window detection fail closed when a guard is requested.
- Browser check does not guarantee zero cross-origin effects from hostile inline JavaScript, popups and delayed navigations. A click cannot be undone. Some legitimate SSO flows will be blocked until a fresh approved plan.
- Exact literal model-grounding rejects some reasonable paraphrases; it prioritizes avoiding silently invented targets over maximum apparent autonomy.
- `code.run` is a deliberate optional trusted-code execution path without an OS sandbox, disabled by default.
- Android input works through authorized ADB from a computer, not as a standalone Android application. iOS arbitrary app control is absent.
- Clap detection accuracy and Thai speech recognition accuracy not benchmarked with physical microphones.
